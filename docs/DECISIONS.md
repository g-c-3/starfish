

**493. ods editing, cell values (Phase 120 step 5a).** `src/js/odsedit.js` edits `content.xml` in place and keeps every other part of the zip as it was, `mimetype` first and not compressed. Same shape as the xlsx engine (names, cell, locked, setCell, merges, snapshot, toBytes, dirty). The sheets are the ones the reader shows (a table with `display` false is left out). A row or cell that stands for several (`number-rows-repeated`, `number-columns-repeated`) is split only where a cell is written; a cell beyond the last row, cell or declared column gets what it needs. Written: a number (`float`; a percent or currency cell keeps its kind and currency), TRUE or FALSE (`boolean`), text (`string`, one paragraph per line; spaces that would collapse are `text:s`, tabs `text:tab`; a leading apostrophe keeps a number as text), clear (value, kind and paragraphs removed, style kept). The cells of a merged cell other than its top left, cells beyond row 5000 or column 200, a formula typed in, a formula cell, and any cell of a workbook that holds formulas are refused with a plain message, because the stored results of formulas that read a changed cell would go out of date and this engine does not calculate them yet. The editor view picks the engine by file type; after each change to an ods it reads the file again (the styles of an ods are not mapped in the view), and shows the Format, Rows and columns and Sheets groups only for an engine that has them. Edit and Save as copy are offered for .ods where they are offered for .xlsx (File explorer, Home, Vault). Not done: formulas, formats, rows, columns and sheets of an ods, dates as dates, notes, pictures. About 14 KB of source added (Decision 453). Next: ods formulas and the rest (step 5b).
