

**492. Number formats in the xlsx editor (Phase 120 step 4b).** A cell's format is the format code of its style. `xlsxedit.js` `setFormat(sheet, row, column, code)` finds the code among the built-in codes, then the workbook's own, else adds a numFmt with the next id above 163 (the numFmts count follows); it copies the cell's style with that code and reuses an equal style when one exists, else appends one to the cell styles (the count follows), and sets the cell's style; General removes the code and, when the style then equals the first one, the cell's style attribute. An empty cell gets a style only; an empty cell back at General is removed. `format` returns a cell's code. Refused with a message: a cell inside a merged cell, a code that is empty, over 80 characters, holds a control character or has an odd number of double quotes, a workbook with no styles part. Nothing is written for a code the cell already has. The value is never changed; text typed in a Text-formatted cell is still stored by the Decision 489 rules. View: the group Format acts on the selected cell (eight presets: General, `0.00`, `0`, `#,##0.00`, `0.00%`, `yyyy-mm-dd`, `hh:mm`, `@`; Custom format asks for a code); the viewer reads the changed file again (Decision 490). The view now keeps the model it is given after each redraw, so shown values use the new styles. `office-read.js` exports `BUILTIN_FMT`. Not done: fonts, colors, borders, alignment, formats of a whole row or column, a format applied to several cells. About 5 KB of source added (Decision 453). Next: ods (step 5).
